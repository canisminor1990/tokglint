# 产品画像

产品名：Tokglint

平台：desktop

产品类型：本机开发者工具。一个进程里同时有系统托盘、任务栏挂件和 React 设置窗口，用来看多个 AI 编程助手的用量。

用户：在自己电脑上同时使用 Claude Code、Codex、Cursor 等工具的人。没有多用户权限。看用量是每天几次，改设置是偶发。

核心任务：

1. 看挂件是否连上，以及已开启的提供商有没有读到用量。
2. 决定哪些提供商显示在挂件上。
3. 调整刷新频率、语言、开机启动和用量倒计时。
4. 为 Claude 和 Codex 维护本机账号配置目录。
5. 打开诊断日志，核对某次读取为什么没有更新。

文案：

copy-profile: devtool

人称用无主语，说明句不写「您」。术语：挂件、提供商、账号、配置目录、默认账号、用量方向、日志记录。不要写成小组件、帐号、账单或额度后台。

适用性：

| 项   | 适用性 | 理由                                       |
| ---- | ------ | ------------------------------------------ |
| P-01 | 强调   | 概览先回答是否连上、哪里读失败             |
| P-04 | 强调   | 删除账号要确认，并写明挂件不再读取哪个目录 |
| P-05 | 强调   | 提供商开关和挂件选项会立刻影响挂件         |
| P-07 | 强调   | 诊断页用来排障，不是空日志占位             |
| P-02 | 不适用 | 设置窗口没有可搜索的对象表                 |
| P-03 | 不适用 | 没有单对象详情页                           |
| P-06 | 不适用 | 没有审批队列                               |
| P-08 | 不适用 | 不是计费对账，只展示本机用量               |
| P-09 | 不适用 | 不是评测或实验平台                         |

任务栏挂件的绘制在 Rust 进程里。设置窗口只负责保存，并通知同一进程。不要在 React 里重画挂件。默认挂件是任务栏里的连续用量条：数字用中性色，读不到显示 --，失败不显示 0%。

非目标：不重写挂件绘制引擎，不把设置窗口做成官网或营销页。
